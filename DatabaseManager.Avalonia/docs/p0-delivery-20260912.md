# P0 交付与验收（2026-09-12）

## 范围

按用户确认，将 Roadmap 原 P1 作为本轮 P0。实现 SSH 隧道、查询结果增强、数据编辑增强、可视化计划、自动化作业五项。ER 图/数据库关系图与完整多数据库实例验收明确跳过。

## 功能与入口

| 功能 | 入口与行为 | 验证 |
| --- | --- | --- |
| SSH | 连接窗口的 SSH 隧道；填写跳板机、用户名、密码或私钥路径、SHA256 主机指纹；数据库主机指 SSH 服务端能访问的地址。仅监听 127.0.0.1，复用隧道，下次操作发现断线时重连；不自动重放 SQL。 | 编译、缺失指纹拒绝、普通连接兼容、窗口渲染；无 SSH 服务端，未完成真实认证/重连联调。 |
| 结果 | 查询结果独立标签；固定最多 3 份快照；“对照”打开两侧独立选择的只读窗口。查询最多保留 64 集、100000 行及约 32 MiB 文本预算，仍读完后续语句以报告错误；超限明确提示。 | SQLite/PG 多结果集与空结果集、100005 行截断、后续语句执行、快照隔离、编辑时阻止切换、对照窗口渲染。 |

## 实测发现并修复

- 批量替换、表单应用后未重新计算待保存状态。
- 对照窗口的行索引绑定不兼容，单元格空白；改用 Values 索引绑定。
- 二进制值进入原 SQL 生成路径时会变成 `System.Byte[]`；按方言生成经过十六进制验证的字面量。
- PostgreSQL 导入读取元数据后再次打开连接导致失败；改为检查连接状态，并传递目标 Schema。
- 导入异常原先丢失具体原因；现保留错误原因。
- 结构对比失败返回空差异会被作业误报成功；增加错误状态，数据同步也拒绝缺失或歧义的表结果。
- 公共连接转换保留各业务服务原来的数据库覆盖/服务器级查询规则。
- 数据编辑事务、执行命令与 SQLite 元数据便利方法补充资源释放。

## 明确限制

- SSH 和 SMTP 真实服务端联调未执行，不能将编译/界面检查视为端到端联调通过；SSH 认证建立有 15 秒超时。
- SQL Server/MySQL/Oracle/KingbaseES 仅代码接入或计划格式解析，未宣称真实实例通过。KingbaseES 迁移沿用现有未验收禁用策略。
- Oracle 二进制字面量限制为 2000 字节；其他数据库沿用驱动/服务端限制。查询结果和表单沿用原系统的字符串显示及空串/NULL 编辑语义，未引入新的强类型网格模型。
- 可视化计划的 SQL 定位基于对象名称，不伪造精确语句偏移；不支持的结构保留原始计划。计划入口仅接受单条 SELECT，ANALYZE 在支持的数据库上会真实执行。
- 同步作业以指定源为准，可能删除目标行/变更目标结构；应在计划启用前确认目标和备份。批处理不是跨步骤分布式事务，也不自动重试可能已经部分执行的写入操作。
- 客户端退出后不执行计划；备份等原有外部工具能力和取消限制保持原有行为。
- 构建仍有历史可空性/未使用字段/Avalonia 资源加载告警。部分 SQLite 临时文件在当前进程内被底层对象持有，测试清理会报告路径；业务断开和进程退出后释放，此问题不当作已解决。

本记录区分“已实现”“自动化通过”“未具备联调环境”，不以 SQLite/PostgreSQL 通过推断所有数据库均通过。
