## 结论与范围

主线 Avalonia 客户端已覆盖连接、对象浏览、SQL 编辑、数据编辑、表设计、迁移、对比、导入导出、备份恢复、任务和监控等功能。功能种类较完整，但不能据此认定所有数据库、界面流程和异常路径均无遗漏。

本次检查了项目功能说明、主线窗口/服务清单、未实现标记，并重点审查 SQL 执行、事务和任务调度。未连接用户业务数据库，也未执行生产数据变更。

## 已修复

| 问题 | 修复结果 |
| --- | --- |
| 手动事务先执行读取，再将无结果 SQL 作为非查询重放，可能重复写入；读取命令未绑定事务 | 查询和非查询统一执行一次，命令显式绑定活动事务 |
| 自动提交把空结果表的行数当成受影响行数 | 使用驱动的 RecordsAffected 获取影响行数 |
| 批量 SQL 后续语句/错误可能未完整处理 | 遍历剩余结果，完成后续语句并报告错误；界面仍展示首个结果集 |
| 事务名区分大小写，与连接查找规则不一致 | 事务字典统一忽略大小写 |
| 断开状态也能开启事务，并发开始可能覆盖已有事务 | 校验连接状态，使用 TryAdd；竞争失败释放新建事务和连接 |
| 定时 SQL 依赖对象树连接状态，并可能加入交互事务 | 使用独立自动提交连接，支持计划指定数据库，不受交互事务影响 |
| 任务超过 100 条时可能移除正在运行的任务 | 仅淘汰已结束任务，运行中任务始终可见、可取消 |
